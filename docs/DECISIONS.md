# Implementation Decisions (Open Technical Decisions)

The specification documents list several open decisions (PRD §15, TRD §17, Security §15).
Per the implementation contract, each is resolved explicitly here with the practical
default chosen to make the MVP runnable — none of these were silently invented.

| # | Decision | Choice | Rationale |
|---|----------|--------|-----------|
| 1 | LLM provider/model | **OpenAI-compatible chat-completions abstraction.** `LLM_BASE_URL` + `LLM_MODEL` + `LLM_API_KEY` env vars. Default: `gpt-4o-mini`. No key → chat returns `503 SERVICE_UNAVAILABLE` with a clear message; the RAG path never silently fakes an answer. | Any OpenAI-compatible endpoint (OpenAI, vLLM, Ollama shim, gateways) plugs in without code changes. Provider identity is never hardcoded per Phase 2. |
| 2 | Embedding provider/model | **OpenAI-compatible embeddings abstraction.** Default `text-embedding-3-small`, dim 1536. `EMBEDDING_DIM` must match the DB vector column; migration parameterizes it via template. | Same portability reasoning as the LLM. Dimension is a DB column definition, so changing it requires a one-line migration — documented. |
| 3 | pgvector configuration | **cosine distance (`<=>`), HNSW index (`vector_cosine_ops`, m=16, ef_construction=64), `vector(1536)` column.** Every query carries `WHERE document_id = :doc_id` **before** similarity ranking. | Spec §06 mandates document-scoped queries and a vector index matching the chosen metric. HNSW is the pgvector default for cosine workloads at MVP scale. |
| 4 | OCR provider | **Not implemented in MVP.** Detection is implemented: scanned/image-only pages set `stage=OCR_REQUIRED` and the document FAILS with safe code `OCR_UNAVAILABLE` and a user-facing explanation (App Flow 09 "OCR unavailable → Explain scanned PDF limitation"). | PRD lists OCR as an open decision / optional; TRD marks it "optional for MVP". Implementing Tesseract silently would violate "do not invent features"; failing safely matches the documented failure path. |
| 5 | Object storage | **LocalFileStorage** — private directory (`STORAGE_DIR`, default `backend/storage/`), random server-generated keys, never exposed via static routes or URLs. `StorageService` interface allows S3/GCS later. | MVP has no cloud account; the Security spec only requires *private* storage and a delete workflow, both satisfied. |
| 6 | Background queue | **DB-backed `processing_jobs` table polled by an asyncio worker loop inside the API process** (startup task). Jobs are idempotent (retry clears chunks+vectors transactionally first). Upgrade path: swap worker for Celery/RQ without touching the jobs table semantics. | No Redis/broker dependency for MVP; spec requires "a job/queue mechanism when processing duration warrants it" — a durable DB job state machine satisfies it and the Database spec defines `processing_jobs` explicitly. |
| 7 | Authentication model | **Anonymous MVP with server-issued session token**: HttpOnly + SameSite=Lax cookie, verified server-side on every document-scoped request. `AUTH_MODE=authenticated` is stubbed (returns 501 with clear message) — the `users` table and `user_id` columns exist per spec. | Security doc: "MVP may use a lightweight session model, but the authorization boundary must be explicit." PRD leaves login as an open decision. All IDOR/authorization tests run against the cookie identity. |
| 8 | Retention period | **MVP: chat data lives with its document.** `DELETE_DEPENDENT_CHAT=delete` removes sessions/messages/sources with the document; the `feedback` table is retained by policy switch only if set to `retain`. Exact retention period remains a documented open product decision. | Privacy spec: "Configurable; MVP can be session-limited." Deleting with the document is the strictest safe default and satisfies the deletion checklist. |
| 9 | PDF limits | **25 MB max size, 300 pages max** (env-tunable `MAX_UPLOAD_MB`, `MAX_PDF_PAGES`). Enforced server-side (413 / 422). | Practical defaults; spec requires configured limits with clear client messages, exact numbers were open. |
| 10 | Source preview | **Not implemented** (PRD: "whether page previews are needed" is open). SourceChip renders page/section from validated server metadata; click-through preview is intentionally absent. | "Do not invent features." UI/UX spec says chips "open source preview only if implemented". |
| 11 | Chunking strategy | Recursive paragraph/sentence-aware split, target ≈450 tokens, overlap ≈60 tokens, page spans preserved (`page_start`/`page_end` per chunk). | TRD requires retrieval-friendly chunks with overlap and preserved page metadata. |
| 12 | Evidence gate | Deterministic: top-1 cosine similarity ≥ `EVIDENCE_THRESHOLD` and top-k non-empty → grounded; otherwise `NO_EVIDENCE`, LLM never called. **The threshold is model-dependent**: OpenAI `text-embedding-3-*` ≈ 0.25 (unrelated texts score ~0), Gemini `gemini-embedding-001` ≈ 0.48 (measured live: unrelated questions 0.42–0.47, on-topic 0.50–0.67 — with boilerplate headers stripped at extraction; the earlier 0.55 value rejected legitimate on-topic questions and was recalibrated). Additionally, if the LLM itself returns the exact no-evidence sentence, the message is stored as `NO_EVIDENCE` with no sources (defense in depth). | TRD 5.2/5.3 and Security §06 require a deterministic threshold; no LLM self-assessment in the gate. |
| 13 | Retry endpoint | `POST /api/v1/documents/:id/retry` added beyond the §09 table. | The lifecycle (FAILED → PROCESSING) and the failure UI (retry action) require it; the §09 table omits it, so this is an explicitly documented addition, not a silent one. |
| 14 | Frontend state management | Zustand (single small store) + typed fetch client; no router (single-workspace app). | Minimal dependency set per Phase 27 ("no unnecessary dependencies"); the app is one screen with state-driven panels. |
| 15 | Markdown rendering | `react-markdown` (no raw HTML) for assistant answers. | FR requires headings/bullets; raw HTML is disabled to keep PDF-derived content inert. |
| 16 | Rate limiting | In-memory sliding-window buckets keyed by session token, separate limits for upload / chat / status endpoints. Single-process only. | Spec requires per-endpoint rate limits; MVP deployment is single-process (documented limitation). |
